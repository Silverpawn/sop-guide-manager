📐 Section A: Siemens Energy Look & Feel, 4-Tab Architecture & 10-Second UX Rule Playbook-Agnostic Platform Standard • Enforced by validate-guides.js
1. Siemens Energy Visual Design System

Deep purple header gradient (#1B1534 → #4D217A), stacked geometric wordmark, fading Petrol accent line (#009999), generous white/light-slate canvas (#FFFFFF / #F8FAFC), and true-to-app colour-matched button badges (Petrol #009999, Bright Purple #8A00E5, Deep Plum #2E1065, Danger Red #DC2626).

2. The 10-Second "Naive Colleague" Rule

Within 10 seconds of landing on any screen, a colleague who does not know internal jargon or software menus must understand what job they are doing, why it matters to business performance, where to start, and which live tool to launch.

3. Universal 4-Tab Shell & 1-to-1 Stage Routing

Every playbook uses the same 4 top tabs (1. End-to-End Journey, 2. Step-by-Step Guides, 3. Decision & Priority Tools, 4. Templates & Reference). Every stage on the Tab 1 Journey Map routes 1-to-1 to its own dedicated Step-by-Step Guide page in Tab 2—never bundle multiple stages into one SOP or display internal database IDs/version numbers.

Section B: Journey Map Cards, Step Brevity & Visual Authenticity

  1. Dynamic N-Stage Journey Maps & Clean 4-Element Stage Cards: Journey Maps dynamically support any number (N) of stages needed by a workflow. Each stage card displays only 4 human elements:
    • 1. Stage Number & Plain-English Title (what this stage is called).
    • 2. What Happens (1–2 sentence conversational summary with zero compliance stamps).
    • 3. Who Is Involved & Tool Used (role ownership + clickable Launch Live Tool ↗ button).
    • 4. What You Finish With (human outcome—never raw .csv / .json extensions or Input → Output: tech labels).
  2. ≤ 20-Word Simplified Technical English (STE) Rule: Every SOP step headline (action) must be 20 words or fewer, start with a direct imperative action verb (Click, Open, Select, Review, Write, Assign, Upload, Export), and contain zero unexplained acronyms.
  3. Predictable Structural Anchors on Every SOP Page: Every Step-by-Step Guide includes a top Kit Bag (Roles, Point-of-Use Tool Drawer, Input & Output), 1. Before You Begin (Setup Checklist), 2. Step-by-Step Instructions (with a mandatory Good Practice Coaching Tip on every step), 3. Buttons & Controls on This Screen (single-screen colour-matched button glossary), and 4. Common Problems & Quick Fixes.
  4. Visual Authenticity & Post-Upload State Rule:
    • Real Screenshots for Software Clicks (type: "image"): Show genuine application screenshots with a positioned highlight box and callout label. If a tool requires a loaded file to reveal its workspace, load sample data before capturing screenshots.
    • Clean Coaching Cards for Human Rules (type: "none"): For discussion, facilitation, or physical steps with no software click, use type: "none" so the right column renders an elevated Coaching Card—never invent fake wireframe UI buttons.
  5. "Guide, Don't Duplicate the App" & Action Focus Rule: Keep guides focused on coaching, visual navigation, decision rules (focusing on 2 to 3 key actions at a time, max 5), and annotated examples—never clone stateful forms that belong inside the live application.

  • Prominent Authoring & Onboarding Controls: Keep 👋 First Time Here?, ✦ Open Authoring Studio, ⬆ Upload Guide (.json), and ⬇ Export Guide ▾ visible in the Top Header Bar and Left Sidebar (never hidden in a footer), with plain-English hover tooltips (data-tooltip) on all primary controls.
  • Full-Viewport Split-Screen Authoring Studio (96vw × 94vh): Opens in a widescreen split workspace with independent scrolling panes and a ⛶ Fullscreen toggle:
    • Tab 1 (Playbook & Journey Builder): Visual form editor for playbook identity, Golden Principle callout, and N-stage cards with live side-by-side preview.
    • Tab 2 (SOP & Step WYSIWYG Editor): Live 20-word counter pill, active-verb/acronym Poka-Yoke checks, Ctrl+V clipboard screenshot paste (auto-compressed to Base64), and click-to-place highlight boxes.
    • Tab 3 (✨ AI Playbook Generator & JSON Importer): 3-step self-service workflow to copy a schema-enforced AI prompt for M365 Copilot / Gemini, paste the returned JSON (auto-stripping markdown fences), run live Poka-Yoke validation, and import directly into the visual editor.
